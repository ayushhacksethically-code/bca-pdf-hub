📘 Detailed Notes

1.1 Software Categories

Application Software: Programs that perform specific tasks for users. Designed to solve a particular problem. Examples: spreadsheets, database systems, desktop publishing, program development software, games.

System Software: More transparent to users; provides a general programming environment where programmers create applications. Offers functions not available at hardware level and manages execution of application programs. Acts as an interface between computer hardware and application software.

The most important type of system software is the Operating System (OS).

1.2 Operating System – Core Definition

Operating System (OS): A collection of programs that acts as an interface between the user of a computer and the computer hardware. Its purpose is to provide an environment in which a user may execute programs.

OS as a Resource Manager: Main resource is computer hardware – processors, storage, I/O devices, communication devices, data. The OS manages these and allocates them to programs and users. Many requests may conflict, so OS decides fairly and efficiently.

Some OS functions (resource management view):

  • Implementing the user interface
  • Sharing hardware among users
  • Allowing users to share data
  • Preventing users from interfering with one another
  • Scheduling resources among users
  • Facilitating input/output
  • Recovering from errors
  • Accounting for resource usage
  • Facilitating parallel operations
  • Organizing data for secure and rapid access
  • Handling network communications

1.3 What is an Operating System? – Expanded

Four main components of a computer system:

  1. Hardware – provides basic computing resources (CPU, memory, I/O).
  2. Operating System – controls and coordinates use of hardware among applications and users.
  3. Application Software – defines how hardware resources are used to solve user problems.
  4. Users – people, machines, or other computers.

Abstract View (Figure 1): Users ↔ Application Software ↔ Operating System ↔ Hardware. The OS sits between users/applications and the bare machine.

OS as a Resource Allocator: Computer resources (CPU time, memory, file storage, I/O) are allocated to programs and users. The OS must resolve conflicting requests fairly and efficiently.

OS as a Control Program: Controls execution of user programs to prevent errors and improper use. Protects system and users from interference.

Two Basic Purposes of an Operating System

  1. Resource allocation and control: Control the allocation and use of computing system resources among users and tasks.
  2. Interface for programmer: Provide an interface between hardware and programmer that simplifies creation, coding, debugging, and maintenance of application programs.

Functions an Effective OS Should Accomplish

  • Command interpreter: Provide a user-friendly environment (shell, GUI).
  • Communication: Facilitate communication with other users (networking).
  • File management: Directory/file creation with security option.
  • I/O handling: Provide routines that handle intricate I/O programming details.
  • Compiler access: Provide access to compilers to translate high-level languages to machine code.
  • Loader: Supply a loader program to move compiled code into memory for execution.
  • CPU scheduling: Ensure fair and non-interfering CPU access when several processes are active.
  • Storage & device allocation: Manage memory and device allocation.
  • Long-term storage: Provide for long-term storage of user information as files.
  • Resource sharing & protection: Share resources when appropriate and protect from unauthorized or mischievous intervention.

Note: Systems programs (editors, translators, utilities like sort and file transfer) are not usually considered part of the OS, but the OS provides access to them.

1.4 Goals of an Operating System

The primary objective of a computer is to execute instructions efficiently and increase productivity of processing resources (hardware, software, users). Maximum CPU utilization is the main objective because the CPU is the core execution device.

Primary Goal: Make the computer convenient to use.

Secondary Goal: Use the hardware in an efficient manner.

In short: convenience first, efficiency second.

1.5 Generations of Operating Systems

Operating systems have evolved alongside hardware/architecture. Five distinct generations are characterized by hardware component technology, software development, and mode of delivery of computer services.

1.5.1 0th Generation (Pre-commercial era)

Time period: Predated commercial production and sale of computers. Dates back to Charles Babbage's Analytical Engine, and later machines: John Atanasoff's computer (1940), Mark I (Howard Aiken & IBM, 1944), ENIAC (Eckert & Mauchly, University of Pennsylvania), and EDVAC (1944-46 by Von Neumann, Burks, Goldstine). EDVAC was the first to fully implement the stored program concept and serial execution of instructions.

Hardware technology: Electronic vacuum tubes.

Operating system: No operating system existed. Early programs were written in machine language and each contained code for initiating operation of the computer itself.

Mode of operation: “Open-shop” – users signed up for computer time. When a user's time arrived, the entire computer system was turned over to that user. The individual programmer was responsible for all machine setup, operation, clean-up, and preparation for the next user.

Drawback: The system was clearly inefficient and dependent on the varying competencies of the individual programmer as operators.

EDVAC set the stage for the evolution of commercial computing and operating system software.

1.5.2 First Generation (1951–1956)

Beginning of commercial computing: Marked by UNIVAC I (Eckert & Mauchly, early 1951) and the IBM 701 (Defence Calculator). Hardware technology remained vacuum tubes.

Closed Shop Operation

Initially still no OS. Mode was called “closed shop” – hired operators appeared. Operators selected the job, performed initial program load (IPL), ran the user’s program, and then selected the next job. Programs began to be written in higher-level, procedure-oriented languages, so the operator’s routine expanded:

  • Select a job.
  • Run the translation program (assembler or compiler) on the source program.
  • Combine the translated object program with any needed library programs using a linking program.
  • Load and run the composite linked program.
  • Handle the next job similarly.

Application programs ran one at a time, translated with absolute computer addresses that bound them to specific storage addresses set by the translator. They obtained data from specific physical I/O devices. No provision for moving a program to a different storage location; if a bound device was busy or broken, the program could not run at all.

Mono-Programmed Operating System

The inefficiencies of the above led to the mono-programmed operating system, which eliminated some human intervention and provided programmers with desirable functions. The OS consisted of:

  • A permanently resident kernel in main storage.
  • A job scheduler and several utility programs kept in secondary storage.

User application programs were preceded by control (specification) cards (submitted on data cards). These cards informed the OS of the required system resources – software resources (compilers, loaders) and hardware resources (tape drives, printers). Systems were designed as batch processing systems.

Operator’s Role and IPL

Systems still operated under a human operator who initiated operation by:

  • Mounting a magnetic tape containing the OS executable code onto a “boot device”.
  • Pressing the IPL (Initial Program Load) or “boot” button to load the OS (bootstrap).

After the system was loaded, the operator entered date and time, then started the job scheduler. The scheduler read and interpreted control statements, secured needed resources, executed the first user program, recorded timing and accounting information, and then processed the next user program from the input queue – repeating as long as jobs waited.

Programming Language Evolution

The first generation also saw a shift from basic machine languages to assembly language, and later to procedure-oriented languages. The most significant development was FORTRAN, created by John W. Backus in 1956.

Remaining Problems

  • Inefficient resource use: CPU waited while slower mechanical I/O devices read/wrote data (CPU idle time).
  • System protection: The operating system kernel was not protected from being overwritten by an erroneous application program.
  • User program isolation: Other user programs in the queue were not protected from destruction by an executing program.

These issues motivated further evolution in subsequent generations.

📋 Summary

Software: Application (user problem solvers) vs System (environment). The Operating System is the core system software, interface between hardware and users/applications. It acts as resource allocator (CPU, memory, I/O) and control program. Primary goal: convenience; secondary: efficiency.

0th Generation: No OS, vacuum tubes, open-shop, machine language. EDVAC introduced stored program concept.

1st Generation (1951–1956): Commercial computing begins (UNIVAC I, IBM 701). Vacuum tubes continue. Closed shop with hired operators, still no OS initially. Programs in higher-level languages led to operator routines (translate, link, load). Inefficiencies prompted the mono-programmed OS with resident kernel, job scheduler, control cards, and batch processing. IPL from magnetic tape. FORTRAN developed. Remaining problems: CPU idle during I/O, no kernel protection, no isolation between user programs.
