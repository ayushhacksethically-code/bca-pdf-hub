📘 Detailed Notes – Types of Operating Systems

1.5 Introduction & Classification

Modern computer operating systems are classified into three groups based on the nature of interaction between the user and the program during processing:

  • Batch
  • Time‑sharing
  • Real‑time

1.5.1 Batch Processing Operating System

Users submit jobs to a central place. Jobs are collected into a batch and placed on an input queue at the computer.

  • User interaction: No interaction with the job during its processing.
  • Response time: Measured as turnaround time – time from submission until execution is complete and results are ready for return.

1.5.2 Time Sharing Operating System

A computer provides computing services to several (or many) users concurrently on‑line.

  • Users share the central processor, memory, and other resources, facilitated and controlled by the OS.
  • User interaction: Nearly full interaction with the program during execution.
  • Response time: Expected to be no more than a few seconds.

1.5.3 Real Time Operating System (RTOS)

Designed to service applications where response time is of the essence to prevent error, misrepresentation, or disaster.

Examples: Airline reservation systems, machine tool control, monitoring of a nuclear power station.

Systems are designed to be interrupted by external signals that require immediate attention.

  • User interface: Very little user‑interface capability; no end‑user utilities.
  • Critical timing: Manages resources so that a particular operation executes in precisely the same amount of time every time it occurs. A part moving faster due to available resources can be as catastrophic as not moving at all.

1.5.4 Multiprogramming Operating System

A multiprogramming OS allows more than one active user program (or part of a user program) to be stored in main memory simultaneously.

Key relationships:

  • A time‑sharing system is a multiprogramming system.
  • A multiprogramming system is not necessarily a time‑sharing system. (Batch and real‑time OS can also have multiple active programs in memory.)

Do not confuse with “multiprocessing”.

1.5.5 Multiprocessing System

A multiprocessing system is a computer hardware configuration that includes more than one independent processing unit (CPU).

Typically refers to large computer hardware complexes used in major scientific or commercial applications.

(Further details in Unit-1 of Block-3 of the course.)

1.5.6 Networking Operating System

A networked computing system is a collection of physical interconnected computers. The OS of each computer must contain, besides stand‑alone functionality, provisions for:

  • Handling communication and transfer of program and data among connected computers.
  • Remote login and remote file access.

Nature: Not fundamentally different from single‑processor OS. It needs a network interface controller and low‑level software, but these additions do not change the essential structure of the OS.

User awareness: Users are aware of multiple computers; they can log in to remote machines and copy files from one to another. Each machine runs its own local OS with its own user(s).

1.5.7 Distributed Operating System

A distributed computing system consists of multiple computers connected and managed to automatically share the job processing load among constituent computers, or separate the load according to specially configured processors.

The OS provides, in addition to stand‑alone functionality, coordination of operations and information flow among the computers.

User perception: A distributed OS appears to its users as a traditional uni‑processor system, even though it is composed of multiple processors. Users should not be aware of where their programs run or where their files are located; this is handled automatically and efficiently by the OS.

Comparison with network OS:

  • In a network OS, users are aware of multiple machines, can log in and copy files.
  • In a distributed OS, there is transparency – everything appears as a single system.

Complexity: True distributed OS require more than adding a little code to a uni‑processor OS. Distributed systems often allow programs to run on several processors at the same time, requiring more complex processor scheduling algorithms to optimise parallelism.

(Further details in Unit-2 of Block-3.)

1.5.8 Operating Systems for Embedded Devices

As embedded systems (PDAs, cellphones, point‑of‑sale devices, VCRs, industrial robot control, toasters) become more complex, applications demand an actual operating system to keep development time reasonable.

Popular embedded OS examples:

  • Nexus’s Conix – an embedded OS for ARM processors.
  • Sun’s Java OS – a standalone virtual machine not running on top of any other OS; mainly targeted at embedded systems.
  • Palm Computing’s Palm OS – leader OS for PDAs, with many applications and supporting companies.
  • Microsoft’s Windows CE and Windows NT Embedded OS.

📋 Summary of OS Types

Operating systems are classified by user interaction: Batch (no interaction, turnaround time), Time‑sharing (concurrent interactive users, fast response), and Real‑time (immediate, deterministic response for critical applications). Multiprogramming runs multiple programs concurrently in memory and is a prerequisite for time‑sharing, though batch/real‑time can also be multiprogrammed. Multiprocessing refers to hardware with multiple CPUs. Network OS connect independent machines with user‑visible remote access, while Distributed OS present a single‑system image with automatic load sharing and transparency. Embedded OS (e.g., Palm OS, Windows CE) are tailored for devices with specific hardware constraints.
