📘 Detailed Notes – Third Generation (1964–1979)

1.5.4 Third Generation Overview

Start: April 1964 with IBM’s announcement of the System/360 family of computers.

Hardware technology: Integrated Circuits (ICs) replaced transistors, offering significant advantages in speed and economy.

Key OS development: Introduction and widespread adoption of multiprogramming.

Advanced Spooling: HASP

The first mark of multiprogramming was more sophisticated I/O buffering in the form of spooling operating systems. A prime example was HASP (Houston Automatic Spooling system) that accompanied IBM OS/360.

HASP introduced two new system programs:

  • System reader: Moved input jobs from cards to disk.
  • System writer: Moved job output from disk to printer, tape, or cards.

To the user, input still appeared to come directly from cards and output directly to the printer (transparent operation).

Exploiting the Data Channel for Multiprogramming

Designers recognized that I/O needed only a CPU instruction to initiate; actual data transmission happened under the separate, asynchronous channel program. By switching CPU control among:

  • The currently executing user program
  • The system reader program
  • The system writer program

...it was possible to keep slower mechanical I/O devices running and minimize CPU idle time. This increased system throughput and resource utilization.

Apparent concurrency: Even though only one CPU existed (executing one instruction at a time), the rapid switching gave the illusion of concurrent operation.

Enhanced Scheduler and Dispatcher

Moving the input queue to disk (a direct access device) freed the scheduler from first‑come‑first‑served. It could now select the “best” next job:

  • Shortest job
  • Highest priority job

Since the CPU was shared by user program, reader, and writer, a processor allocation rule was needed. The goal was to keep I/O devices running asynchronously with user processing. I/O processing needed the CPU only briefly to initiate channel instructions, so the dispatch order was:

  1. Reader
  2. Writer
  3. User program

If the writer or user program was executing when something became available to read, the reader would preempt the currently executing program. Similarly, the writer would preempt the user program. This was called the static priority rule with preemption, implemented via a system dispatcher.

Full Multiprogramming and Memory Management

The spooling OS already had multiprogramming because more than one program was resident in main storage. The idea was extended to include more than one active user program in memory simultaneously. Consequently:

  • Scheduler: Enhanced to manage the diverse resource needs of multiple concurrently active programs.
  • Dispatcher: Included policies for allocating processor resources among competing user programs.
  • Memory management: Became more sophisticated to ensure that at least the active part of each job’s code was resident in main storage.

Hardware Innovations Enabling Multiprogramming

Large‑scale multiprogramming was made possible by several important hardware developments:

  • Large‑capacity, high‑speed disks: Accommodated spooled input streams, memory overflow, and several concurrently active programs.
  • Relocation hardware: Facilitated moving blocks of code within memory without excessive overhead.
  • Storage protection hardware: Ensured user jobs were protected from one another, and the OS itself was protected from user programs.
  • Extended interrupt system: Handled external conditions beyond I/O: program malfunctions, storage protection violations, machine checks. The interrupt system also became the method for a user program to request OS services (system calls).
  • Privileged instructions: Allowed the OS to maintain coordination and control over multiple concurrent activities.

Time‑Sharing: A New Way of Delivering Computing

Successful multiprogramming opened the door to time‑sharing. In this environment:

  • Multiple terminals (up to 200) were attached to a central computer via hard wiring or telephone lines.
  • Users “logged in” and worked interactively with the system.
  • The apparent concurrency was enabled by the multiprogramming OS.
  • Users shared the system’s hardware, software resources, and file system disk space.

Significance of the Third Generation

The third generation was an exciting period for both hardware and OS development. During this era, the topic of operating systems became a major element of the discipline of computing.

📌 Generational Progression (Quick Recap)

0th: No OS, vacuum tubes, open shop.

1st (1951‑56): Vacuum tubes, closed shop, mono‑programmed batch, FORTRAN.

2nd (1956‑64): Transistors, data channel, interrupts, buffers, spooling, CTSS time‑sharing experiment.

3rd (1964‑79): ICs, IBM System/360, multiprogramming (HASP spooling, reader/writer), static priority preemption, advanced memory management, privileged instructions, time‑sharing terminals, OS established as a major computing field.

📋 Summary of the Third Generation

The third generation (1964–1979) was launched by IBM System/360 and built on integrated circuits. The era’s defining OS advancement was multiprogramming, first seen in sophisticated spooling systems like HASP, which used a system reader and writer to move jobs between cards, disk, and printer, while transparently keeping I/O devices busy. The CPU was switched rapidly among the user program, reader, and writer according to a static priority with preemption rule, maximising throughput.

Multiprogramming was extended to multiple active user programs, supported by hardware innovations: large disks, relocation hardware, storage protection, extended interrupts, and privileged instructions. Schedulers could now prioritise jobs, and memory management became more sophisticated. These capabilities made time‑sharing viable, allowing dozens of users at terminals to interact with the central computer concurrently. The third generation cemented the operating system as a core discipline of computing.
