📘 Detailed Notes – Second Generation (1956–1964)

1.5.3 Second Generation Overview

Hardware technology: Transistors replaced vacuum tubes, making computers more reliable and smaller. Important changes in hardware and software architecture occurred.

System orientation: Computer systems remained primarily card and tape‑oriented. Significant use of random access devices (disks) appeared only toward the end of the generation. Program processing was mostly done on large centralized computers running mono‑programmed batch operating systems.

The I/O Wait Problem

Programs executed instructions strictly sequentially. The fast CPU often had to wait for slow mechanical I/O devices (card readers, tape drives). This forced idle time severely reduced efficiency.

Data Channel

Definition: An integral, special‑purpose computer with its own instruction set, registers, and control unit, designed to handle I/O operations separately and asynchronously from the main CPU. Introduced near the end of the first generation and widely adopted in the second.

Function: Allowed I/O buffering and I/O overlap.

  • Buffering: Input data could be read “ahead” from cards/tape into a memory buffer. When the program needed data, it transferred from the buffer at main memory speed, not the slow device speed. Output similarly buffered.
  • I/O overlap: The data channel worked concurrently with the main CPU. While the CPU executed program instructions, the channel performed mechanical I/O operations. This reduced CPU idle time.

The channel was controlled by a channel program set up by the OS I/O routines and initiated by a special CPU instruction.

Polling and the Invention of Interrupts

Initially, communication from the channel to the CPU was handled by polling – the CPU periodically stopped to check the channel for messages. Polling was inefficient.

Interrupt: A major innovation of the second generation. The data channel could interrupt the CPU with a signal, usually “I/O complete”. The interrupt concept was extended to signal exceptional conditions:

  • Arithmetic overflow
  • Division by zero
  • Time‑run‑out (using an interval timer)

The interval timer gave the OS a way to regain control from an exceptionally long or infinite loop program.

Operating System Enhancements

These hardware developments led to significant OS improvements:

  • I/O and data channel communication became OS functions – relieved programmers from complex I/O programming and protected system integrity.
  • Improved service to users by segmenting jobs: shorter jobs could run first (during “prime time”), longer jobs relegated to lower priority or nighttime runs.
  • System libraries became more comprehensive, offering new utilities and application software components.

Spooling (Simultaneous Peripheral Operations OnLine)

To further reduce I/O wait, systems were set up to spool input/output:

  • User jobs submitted at a window; a batch accumulated.
  • Cards were spooled to magnetic tape off‑line (on a smaller satellite computer).
  • The tape was moved to the main computer, jobs ran, and output was written to another tape.
  • The output tape was taken to a satellite computer for off‑line tape‑to‑printer conversion.
  • Users picked up printed output at the submission window.

This allowed the main computer to work at tape speed, not card reader/printer speed.

Shift to Disk‑Oriented Systems and Virtual Machine

Toward the end of this period, random access devices (disks) became available. Tape‑oriented operating systems began to be replaced by disk‑oriented systems. With more sophisticated disk hardware and the OS supporting a greater portion of the programmer’s work, the system appeared as a virtual machine – more and more removed from the actual hardware.

Remaining Limitations and the Path Forward

The second generation was a period of intense OS development, but sequential batch processing (one job at a time) was still a major limitation.

  • Low CPU utilization for I/O‑bound jobs.
  • Low I/O device utilization for CPU‑bound jobs.

Computers were still large and expensive, so researchers began experimenting with multiprogramming and multiprocessing – leading to time‑sharing systems. A noteworthy example: the Compatible Time Sharing System (CTSS), developed at MIT in the early 1960s.

📋 Summary of the Second Generation

The second generation (1956–1964) used transistors instead of vacuum tubes. The critical innovation was the data channel, a separate I/O processor that enabled buffering and I/O overlap. Initially, CPU‑channel communication relied on polling, but the interrupt mechanism replaced it, later extended to handle arithmetic exceptions and time‑outs.

Operating systems absorbed I/O control, supported job segmentation and system libraries, and introduced spooling (card‑to‑tape and tape‑to‑printer off‑line). Toward the end, disks began replacing tapes, and the idea of a virtual machine emerged. Despite these advances, sequential batch processing still caused low resource utilization. This spurred research into multiprogramming and time‑sharing, exemplified by MIT’s CTSS. These notes cover the full evolution, problems, and solutions of the second generation for exam preparation.
