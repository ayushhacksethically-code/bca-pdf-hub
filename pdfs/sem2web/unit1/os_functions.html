📘 Complete Unit Notes (Sections 1.1 – 1.8)

1.1 – 1.3: Software, OS Definition & Purpose

Application Software: User‑focused problem solvers (spreadsheets, DB, games). System Software: Provides programming environment; OS is the most important.

Operating System: A collection of programs acting as interface between user and hardware. Its purpose: provide an environment to execute programs.

Four Components: Hardware (CPU, memory, I/O) → OS → Application Software → Users.

Two Basic Purposes: 1. Resource allocation & control. 2. Simplify program creation, debugging, maintenance.

Functions: Command interpreter, communication, file management, I/O routines, compiler access, loading, CPU scheduling, storage allocation, long‑term file storage, resource sharing & protection.

Abstract View (Figure 1): Users ↔ Application ↔ OS ↔ Hardware.

1.4 Goals of an OS

Primary: Make the computer convenient to use.
Secondary: Use the hardware efficiently (maximize CPU utilization).

1.5 Generations of Operating Systems

0th Gen: No OS, vacuum tubes, open‑shop. EDVAC introduced stored program concept.

1st Gen (1951‑56): Vacuum tubes. Closed shop, hired operators. Mono‑programmed batch OS with control cards, resident kernel, job scheduler. IPL from tape. FORTRAN (1956). Problems: CPU idle during I/O, no protection.

2nd Gen (1956‑64): Transistors. Data channel → I/O buffering & overlap. Interrupts replaced polling, extended to time‑outs. Spooling (card→tape→disk). Disk‑oriented systems emerged, virtual machine concept. CTSS time‑sharing experiment.

3rd Gen (1964‑79): ICs, IBM System/360. Multiprogramming via HASP spooling (system reader/writer). Static priority preemptive dispatching. Hardware: relocation, storage protection, privileged instructions. Time‑sharing (up to 200 terminals). OS became a major computing discipline.

1.5 Types of Operating Systems

Batch: Jobs collected, no user interaction, turnaround time.

Time‑sharing: Multiple concurrent interactive users, response < few seconds.

Real‑time (RTOS): Immediate response to external events; airlines, nuclear plant. Very little UI; guaranteed execution time.

Multiprogramming: Multiple active programs in memory simultaneously. Time‑sharing is a form of multiprogramming.

Multiprocessing: Hardware with more than one CPU.

Network OS: Interconnected computers; users aware of remote machines, remote login/file access.

Distributed OS: Appears as single uni‑processor system; transparent job and file location, complex scheduling for parallelism.

Embedded OS: For devices (PDAs, phones). Examples: Palm OS, Windows CE, Java OS, Nexus Conix.

1.6 Desirable Qualities of OS

Usability: Robustness, consistency, proportionality, convenience, powerful high‑level facilities.

Facilities: Sufficient, complete, appropriate for intended use.

Cost: Low cost, efficient algorithms (space/time tradeoffs), low overhead (idle time minimal), low maintenance.

Adaptability: Tailored to environment, changeable over time (new devices, users), extensible (new features look like old).

1.7 Operating System Examples

DOS: First widely‑installed PC OS, single‑user, command‑line, underlying Windows 3.1–ME, emulated in NT/2000/XP.

UNIX: Written in C, open systems, kernel + file system + shell. Many variants (Solaris, Linux, AIX). Over 600 commands; Motif GUI.

Windows: Success due to built‑in networking; de facto standard with Office. Complexity and compatibility issues exist, but improved resilience in 2000/XP.

Macintosh: First widely‑sold PC with GUI (1984); icons, mouse, windows. Mac OS X, PowerPC. Popular in graphic design (≈5% market).

User Classes: Command language users (shell) and system call users (runtime calls in programs).

1.8 Functions of an Operating System

The main functions are:

  1. Process Management
  2. Memory Management
  3. Secondary Storage Management
  4. I/O Management
  5. File Management
  6. Protection
  7. Networking Management
  8. Command Interpretation

1.8.1 Process Management

A process is a program in execution (batch job, time‑shared program, system task like spooling). The OS handles:

  • Creation and deletion of user & system processes.
  • Suspension and resumption of processes.
  • Mechanisms for process synchronization.
  • Mechanisms for deadlock handling.

(Further study: Unit‑2 of this course)

1.8.2 Memory Management

Memory is a large array of addressable words/bytes. CPU fetches and stores data via reads/writes. OS responsibilities:

  • Track which parts of memory are in use and by whom.
  • Decide which processes to load when memory becomes available.
  • Allocate and deallocate memory space as needed.

Choice of memory management scheme depends on hardware design. (Detailed in Block‑2, Unit‑1)

1.8.3 Secondary Storage Management

Main memory is too small; programs/data stored on disk. Disks are primary on‑line storage. OS manages:

  • Free space management.
  • Storage allocation.
  • Disk scheduling.

Tapes are sequential and slower, used for infrequent files. (Block‑2, Unit‑3)

1.8.4 I/O Management

OS hides device peculiarities from users. In UNIX, I/O system hides them even from the bulk of the OS. OS provides:

  • A buffer caching system.
  • General device driver code activation.
  • Specific driver software for each hardware device.

(Block‑2, Unit‑3)

1.8.5 File Management

OS provides a uniform logical view of information storage, abstracting physical devices. A file is a logical storage unit (sequence of bits/bytes/records). OS responsibilities:

  • Creation and deletion of files.
  • Creation and deletion of directories.
  • Primitives for manipulating files and directories.
  • Mapping files onto disk storage.
  • Backup of files on stable storage.
  • Protection and security of files.

1.8.6 Protection

Protection ensures that only authorized processes access resources. Mechanisms include:

  • Memory addressing hardware – restricts process to its own address space.
  • Timer – prevents CPU monopoly.
  • No direct I/O for user processes – protects devices.

Protection controls access to resources and improves reliability by detecting errors at interfaces. Early detection prevents contamination. (Block‑3, Unit‑4)

1.8.7 Networking

A distributed system is a set of processors without shared memory or clock; each has local memory, communicating via lines. The communication network design must address routing, connection, and security. Benefits: resource sharing, computation speed‑up, data availability, reliability.

1.8.8 Command Interpretation

The command interpreter is the primary user interface. In batch, it's the control card interpreter; in time‑sharing, the shell (UNIX). It reads and executes control statements. Commands deal with process management, I/O, secondary storage, memory, file system, protection, and networking.

📋 Final Summary of the Unit

The operating system is the core system software, serving as interface, resource allocator, and control program. Its goals are convenience and efficient hardware use. Evolution moved from no OS (0th gen, open‑shop) through batch mono‑programmed systems (1st gen), interrupts and spooling (2nd gen), to multiprogramming and time‑sharing (3rd gen). OS types include Batch, Time‑sharing, Real‑time, and specialised forms like Multiprogramming, Multiprocessing, Network, Distributed, and Embedded systems. Qualities focus on usability, facilities, cost, and adaptability. Popular systems: DOS, UNIX, Windows, Macintosh. The eight core functions—Process, Memory, Secondary Storage, I/O, File, Protection, Networking, and Command Interpretation—together manage all hardware resources, provide user interfaces, and ensure secure, efficient computing.
